# 0028 — MCP opcionales con onboarding guiado: `/lf:mcp` y `--mcp=`

Fecha: 2026-11-26

Decisión: `/lf:setup` pregunta qué MCP montar (Playwright, GitHub, Atlassian y Figma; ninguno por defecto), guarda la elección en `~/.claude/lf/config.json` (`optional.mcp`) y, en el paso 3b, encadena `/lf:mcp <nombre>` con la herramienta Skill. `plugins/lf/commands/mcp.md` (`/lf:mcp [playwright|github|atlassian|figma …]`; sin argumento usa `optional.mcp`) hace el onboarding de cada uno: ya montado (`claude mcp get`, o conector de claude.ai equivalente) → requisitos → alta → login OAuth si procede → verificación → una prueba de solo lectura para la próxima sesión → permisos y cómo deshacer. `plugins/lf/docs/MCP.md` es la fuente única: una ficha por MCP con 9 campos (`Para qué`, `Vía`, `Requisitos`, `Comando`, `Auth`, `Verificar`, `Contexto`, `Permisos`, `CLI mejor cuando`); `mcp.md` la lee y no copia comandos.
Reglas: alcance `user`, sin versión fija y sin tokens literales (`Bearer`, `ghp_`, `github_pat_`). Claude ejecuta el `Comando` de la ficha con aviso de permiso; si el usuario lo deniega, se le da el `! …` y se sigue. GitHub usa `headersHelper` con `gh auth token` (la doc de Claude Code admite comando en línea; no hace falta helper en `install.sh`). `install.sh --mcp=<lista>` solo valida y guarda: regex estricta (sin vacíos ni espacios), `unique` ordena alfabéticamente, sin flag conserva lo guardado normalizado contra la lista cerrada, `--mcp=` la limpia; nunca ejecuta `claude mcp add`. El estado real de cada MCP no se guarda: manda `claude mcp get <n>`. Deshacer es `claude mcp remove <n> -s user`; `logout` solo con login OAuth (Atlassian, Figma). La pregunta de MCP es la 4.ª de la llamada única de 0b y el paso 3b se salta con `--only=` sin `config` o con `--rollback`.
Desvíos respecto al contrato: (1) `mcp.md` va sin `disable-model-invocation` porque setup lo invoca con Skill; (2) la prueba manual con Playwright mostró que sugerir `logout` para un MCP sin OAuth era un error, de ahí la regla de deshacer.
Límites: solo se probó a mano el onboarding de Playwright. Sin verificar: el `add-json` real de GitHub, `headersHelper` en Windows nativo, el comando legacy `-H` (la ficha remite a la doc de github-mcp-server) y el onboarding de GitHub, Atlassian y Figma. Atlassian v1 migra el 2027-03-01 (la ficha usa la URL v2) y Rovo consume créditos; en Figma, escribir en el lienzo exige plan de pago.
Descartado: solo `! …` en el alta (más fricción; queda como plan B); onboarding embebido en setup (no se puede repetir aislado); reglas `allow`/`ask` escritas (los nombres de herramienta cambian entre versiones); PAT en cabecera o variable de entorno para GitHub; el plugin de Figma como vía principal (más contexto y algunas organizaciones bloquean plugins); `.mcp.json` de proyecto; medir tokens; desinstalación automática.
