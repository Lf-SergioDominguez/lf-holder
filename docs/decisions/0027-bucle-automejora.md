# 0027 — Bucle de automejora: `/lf:improve` y `scripts/improve.mjs`

Fecha: 2026-11-26

Decisión: `scripts/improve.mjs` (repo, sin dependencias, determinista y sin red) cruza por versión del plugin las evals (`plugins/lf/evals/results/summary.jsonl`) y la telemetría (`<métricas>/<proyecto>/<versión>/<ejecución>/report.json`, del clon de `lf-holder-metrics`, `--metrics` o `$LF_METRICS_DIR`). Imprime Markdown (o `--json`, schema 1) con una tabla por versión, los casos **sin señal** (|Δ with-without| < 0,05) y las **regresiones** entre versiones consecutivas con dato. `plugins/lf/commands/improve.md` (`/lf:improve`) ejecuta el script, redacta 1–3 propuestas (`Hipótesis`, `Cambio`, `Métrica`, `Cómo medir`) y escribe `docs/improve/AAAA-MM-DD.md`. Solo propone: no edita el plugin ni lanza evals; aplicar y medir es un hito M aparte, y el ADR de cada propuesta se escribe al medir.
Reglas: reutiliza `readHistory`, `SCORE_DROP` y `COST_RISE` de `evals-compare.mjs` y `validate` de `telemetry.mjs` (una sola regla de regresión). Regresión: score de caso baja >0,10; coste de caso, tokens/petición, contexto del primer turno, `deny` y errores de hooks por 100 sesiones suben >30 %; `autocompact` sube >5 puntos. Con base 0, `deny` y errores de hooks cuentan como regresión con cualquier subida (0 → N); en el resto, base 0 no se compara. Telemetría: se descartan los informes que no pasan `validate()` o con `sessions` = 0 (cuentan como `skipped`); tokens ponderados por peticiones, contexto y autocompact por sesiones, `ask`/`deny`/errores por 100 sesiones. Exit 0 aunque falte el directorio de métricas o haya regresiones (informe, no gate); exit 1 solo con argumento inválido. Guard del comando: sin `scripts/evals.sh` y `scripts/improve.mjs` en el cwd no hace nada.
Desvíos respecto al contrato: (1) el coste de un caso es la media de sus líneas `none` de la versión y el de la versión la suma de sus casos, no «la línea más reciente»: `summary.jsonl` mezcla pasadas de un caso, completas y `with-without` (~2x) y daba falsas regresiones; (2) `render(data, metricsName)` recibe el nombre del directorio de métricas para el aviso sin ruta; (3) métricas de regresión de evals `score <id>` y `costUsd <id>`; (4) `readReports` devuelve `{ reports, skipped }` y `withTelemetry` une la telemetría a las versiones de evals (crea las que solo tienen telemetría).
Límites: `summary.jsonl` está ignorado por git, así que el informe refleja solo las evals de esa máquina y no habrá regresiones entre versiones hasta lanzar evals con 1.0.6; el clon de métricas puede estar vacío («sin datos de telemetría», exit 0). `telemetry.mjs` decide `variant` con `/public/i` sobre `repository`, y el público envía `variant: private`; no afecta al agrupado (por `plugin_version`) y se arregla aparte.
Descartado: que Claude calcule las métricas (no testeable sin tokens); el script en `plugins/lf/scripts/` (lo recibiría el equipo); agrupar por proyecto o deducirlo de `repository`; `--out` en el script (lo escribe el comando); `git pull` automático del clon de métricas.
